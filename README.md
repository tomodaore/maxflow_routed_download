# maxflow_routed_download

複数の中継サーバーを利用してファイルを転送するシステムです。

各ノード間の通信帯域を測定し、その値をグラフの辺容量として扱い、Edmonds-Karp法で最大流と利用経路を求めます。求めた経路のうち、最大流全体の90%をカバーする経路を採用し、残りのファイルを各経路の流量比に応じて分割して並列ダウンロードします。

本作品は**チーム制作**です。作品全体を自分一人で制作したものではなく、下記の「自分の担当箇所」に記載した処理を主に担当しました。

## 作品概要

ファイルサーバーからクライアントへファイルを転送する際に、直接通信だけでなく複数の中継サーバーを利用できる環境を想定しています。

クライアント側では、経路計算とファイル受信を並行して行います。

1. ファイルサイズを取得
2. 経路計算が終わるまではファイルサーバーから直接ファイルの一部を受信
3. クライアントと各中継サーバー間の帯域を測定
4. 各中継サーバーから他ノードとの帯域情報を収集
5. 帯域情報からグラフを作成
6. Edmonds-Karp法を用いて最大流と利用経路を計算
7. 利用経路を流量の大きい順、同流量ならホップ数の少ない順に並べる
8. 最大流全体の90%をカバーするまで経路を採用
9. 残りのファイルを32KB単位のチャンクに分割
10. 採用した各経路の流量比に応じてチャンクを割り当てる
11. 複数経路で並列にファイルを取得
12. 受信したチャンクを元の順番に結合

中継サーバー側では、帯域測定用データの送信、他ノードとの帯域測定、次の中継サーバーまたはファイルサーバーへの通信中継などを行います。

## 経路決定の方法

各ノード間で測定した帯域を `band` 行列に格納し、その値をグラフの辺容量として使用します。

`edmonds_karp_with_paths` では、BFSを利用して増加路を探し、各経路のボトルネック分だけフローを流す処理を繰り返します。その際、実際に使用した経路と、その経路に割り当てられた流量を `used_paths` に保存します。

最大流の計算後、

```python
used_paths.sort(key=lambda x: (-x[1], len(x[0])))
```

として、

1. 流量が大きい経路
2. 流量が同じ場合はホップ数が少ない経路

の順に並べます。

その後、`alpha = 0.9` として、採用した経路の累積流量が全経路の流量合計の90%に達するまで `routes` と `weights` に追加します。

例えば利用経路の流量が、

```text
route A : 50
route B : 30
route C : 10
route D : 10
```

の場合、合計流量は100なので、A・B・Cを選択した時点で90に達し、この3経路を利用します。

## ファイルの分割と並列ダウンロード

経路計算が完了すると、それまで直接ダウンロードしていた位置から後ろのデータを `CHUNK_SIZE = 32 * 1024` バイト単位に分割します。

各経路へのチャンク数は、`weights` に保存された流量の比率を使って決定します。

例えば、

```text
route A : 80
route B : 40
```

なら、おおよそ2:1の比率でチャンクを割り当てます。

端数が発生する場合は最大剰余法で調整し、全チャンクがいずれかの経路に割り当てられるようにしています。

各経路ごとにスレッドを作成し、中継サーバーへ経路情報を送った後、担当する範囲を `GET ... PARTIAL` で取得します。

最後に受信したチャンクを元の順番に並べてファイルへ書き込みます。

## 自分の担当箇所

自分が実装を担当したのは主に `client.py` 側です。

特に、中継サーバーへ帯域測定を依頼し、その結果を受け取って帯域情報をまとめ、最大フローを用いて利用経路を決定する処理と、それに関連するファイル受信・スレッド制御を担当しました。

担当した関数は以下です。

- `input_pgs_name`
  - `pgs.txt` から中継サーバー一覧を読み込む処理

  - 実行ログの記録
- `thread_file_recv`
  - 経路計算中のファイル受信と、経路決定後の受信処理への切り替え
- `measure_max_bps`
  - クライアントから中継サーバーへ帯域測定用データの送信を要求し、受信量と時間から帯域を算出
- `measure_file_bps`
  - ファイルサーバーとの通信帯域を測定
- `input_pg_bandwidth`
  - 中継サーバーへ `MEASURE_ALL` を送り、各ノード間で測定された帯域情報を受信して保存
- `edmonds_karp_with_paths`

- `thread_route_manager`
  - 帯域測定を並列に実行し、測定結果から帯域行列を作成して最大フローを計算し、利用経路を決定
- `threading_download`
  - ファイル受信処理と経路計算処理を並行して実行するスレッド制御

`relay_main.py` はチーム制作で使用した中継サーバー側のプログラムですが、**このファイルに自分が実装した箇所はありません**。

## 実行環境・実行方法

このプログラムは、複数のホストが存在するネットワーク環境を前提としています。

### 中継サーバー

各中継サーバーで、

```bash
python3 relay_main.py
```

を実行します。

`relay_main.py` は実行したホスト名を取得し、コード内の `NODE_MAP` に対応するポートで待ち受けます。

中継サーバー用ポートは `54300`、ファイルサーバー用ポートは `60623` を使用します。

### クライアント

最新版の `client.py` は次の形式で実行します。

```bash
python3 client.py <server_host> <filename> <token>
```

- `server_host`：転送対象ファイルを保持するサーバー
- `filename`：取得するファイル名
- `token`：鍵生成に使用するトークン

ファイルサーバーのポートは `FILE_SERVER_PORT = 60623` としてコード内で指定しています。

実際の動作には、

- `pgs.txt` に記載された中継サーバー
- 各中継サーバーで動作する `relay_main.py`
- 授業で配布された `pbl2.py`
- 転送対象ファイルを保持し、SIZE / GET / REP 等の要求を処理するファイルサーバー

が必要です。

そのため、一般的なPC1台で簡単に動作確認する形式ではなく、複数ホストを使用した制作環境を前提とした作品です。
