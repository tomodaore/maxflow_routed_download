## 作品概要

ファイルサーバーからクライアントへファイルを転送する際に、複数の中継サーバー間の通信帯域を計測し、その結果から転送に利用する経路を決定することを目的として制作しました。

クライアント側では、

1. ファイルサイズを取得
2. 中継サーバーとの通信帯域を計測
3. サーバー間の帯域情報を収集
4. 帯域情報からグラフを作成
5. Edmonds-Karp法を用いて最大フローと経路を計算
6. 転送処理と並行して経路計算を実行

という流れを扱っています。

## 自分の担当箇所

以下の関数・処理を担当しました。

- `input_pgs_name`
  - 中継サーバー一覧の読み込み
- `log_print`
  - 実行ログの記録
- `thread_file_recv`
  - ファイル受信処理
- `measure_max_bps`
  - クライアントと中継サーバー間の帯域計測
- `measure_file_bps`
  - ファイルサーバーとの帯域計測
- `input_pg_bandwidth`
  - 各中継サーバーから帯域情報を収集する処理
- `edmonds_karp_with_paths`
  - Edmonds-Karp法による最大フロー計算と経路復元
- `thread_route_manager`
  - 帯域計測・グラフ作成・経路計算の管理
- `threading_download`
  - ファイル受信と経路計算を並行して実行するスレッド制御

上記以外のコードについては、チームメンバーが担当した部分や、チームで共有して実装した部分を含みます。

## 実行方法

このプログラムは、単体で完結する一般向けアプリケーションではなく、複数のサーバーが動作するネットワーク環境を前提としています。

クライアント側は概ね次の形式で実行します。

```bash
python3 client.py <server_host> <server_port> <filename> <token>
```

例：

```bash
python3 client.py pg1 5000 sample.dat TOKEN
```

実際の動作には、

- `pgs.txt` に記載された中継サーバー
- 中継サーバー側プログラム
- `pbl2.py`
- 転送対象ファイルを保持するサーバー

が必要です。

そのため、一般的なPC1台だけでの完全な再現は難しく、主にソースコードと処理内容を確認してもらうことを想定しています。
